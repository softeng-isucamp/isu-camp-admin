Closes #143.

A superadmin switches four general permissions on or off for each regular administrator, and **every write route enforces its own**. Frontend gating hides buttons; this is the part that refuses the request.

**Viewing is deliberately not a switch.** It is the least-privilege minimum every active account keeps, so an administrator who should see nothing is deactivated instead.

## Part A — storage and responses

`public.admin.permissions` is one `jsonb` object with a shape constraint, so a row cannot hold anything but the four booleans.

**`NULL` means every permission.** That is what makes the column safe to add to a running deployment: the migration backfills existing administrators with all four **on**, superadmins stay `NULL`, and a row nobody configured keeps the access it had. New accounts and demoted superadmins start with all four **off** — an account being set up has not been given anything yet.

`POST /api/login`, `GET /api/me` and `GET /api/admins` all carry the same object, `null` for a superadmin:

```json
{"id":"7","username":"registrar","role":"admin",
 "permissions":{"add":true,"edit":false,"delete":false,"changeUserStatus":true}}
```

Read from the row on **every request**, never from the session cookie, so withdrawing a permission takes effect on the administrator's next request rather than at their next sign-in.

## Part B — administrator management

`PUT /api/admins/:id/permissions` — superadmin-only behind a recent password confirmation, the same pattern as `/role`:

| Case | Status | Message |
| --- | --- | --- |
| The target is the caller | 409 | `You cannot change your own permissions.` |
| The target is a superadmin | 409 | `Superadmins always have every permission. Demote them first to restrict them.` |
| A partial or mistyped set | 400 | `Each of the four permissions must be given as true or false.` |
| Done | 200 | `Permissions updated for <username>.` |

Audited as what moved — `admin02: add: on -> off; delete: on -> off`.

`POST /api/admins` accepts an optional `permissions` object and now requires a password confirmation for **every** create, not only a superadmin's. `PUT /api/admins/:id/role` accepts `permissions` on a demotion and discards them on a promotion.

**`DELETE /api/admins/:id` answers 405.** Removing the row orphaned the audit trail, which names an actor by username; `PUT /api/admins/:id/status` does the same job and keeps the history readable.

## Part C — enforcement

`auth.permission_required` (and `permission_error`, where a route has already loaded its caller) guards all 19 write routes and refuses with:

```json
{"success":false,"code":"PERMISSION_DENIED","message":"You don't have permission to do that. Ask a superadmin."}
```

On a delete the **permission is checked before the password confirmation**, as with `superadmin_required` — an administrator who may not delete is told so rather than asked to confirm a password for an answer that was never going to be yes.

### Operations, not request verbs

- **`PATCH .../indoor-locations/:id`** needs `add` for a marker's first placement and `edit` to move or clear one it already has. Decided from the marker's **stored coordinates**, so a client cannot choose the permission it is judged against.

- **`PUT /api/pathways/:id/points`** (new) replaces a pathway's whole point sequence as one `edit`, in one transaction. Reshaping stores new vertices and drops old ones; reconciled one vertex at a time it reached the server as an add, an edit *and* a delete — so an administrator who may edit the network could only drag a shape that kept its vertex count, and a refusal partway through left the pathway holding half of its new shape. The adapter now sends the shape in one request. Creating a pathway already carries its vertices, and Create Junction / Convert to Route Node stays one `add` including the graph rewiring it requires.

- **`POST /api/map/save`** is checked **per change in the payload**, before the first one is applied: one refused change refuses the whole save, and the message names it (`You don't have permission to change the Engineering Hall footprint. Ask a superadmin.`).

- **`POST /api/map/publish`** stays open to every active administrator, as the issue asked: it promotes work that is already saved, and the saving is what each permission was checked on.
